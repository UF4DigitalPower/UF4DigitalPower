# 状态机设计说明

## 范围与现状

本文整理 `Upper/STM32G474RBT6` 的功率控制实现，为后续在 G474 工程中维护或迁移状态机提供约定。本文是设计与检查清单，不表示 `STM32G474BMP` 已实现这些迁移。BMP 工程当前的 `User/3_Communicator/pc_main.c` 仅包含通信示例使用的状态寄存器。

RBT6 的主要入口如下：

| 职责                           | 当前实现                                                               | 执行上下文            |
|------------------------------|--------------------------------------------------------------------|------------------|
| 功率生命周期及启停、换向、故障恢复            | `USER/App/system_sm.c`                                             | 主循环前台            |
| 命令快照和通信授权                    | `USER/App/command_mailbox.c`、`USER/Communication/uf4com_adapter.c` | 主循环前台            |
| 软件故障锁存、闭环运行许可                | `USER/Control/power_control.c`                                     | 前台与中断            |
| 比较器/HRTIM 保护和输出门控            | `USER/Bsp/power_hw.c`                                              | 硬件与中断            |
| 电压/电流调节、软启动斜坡、Buck/Mix/Boost | `USER/Control/power_regulator.c`                                   | 10 kHz/50 kHz 中断 |
| 串口字节解析、链路、Flash 保存           | 各自模块                                                               | 独立流程，不属于功率生命周期   |

基本规则：**命令是请求，状态是事实，故障是独立锁存，方向与控制模式是正交维度。** 不把方向、Buck/Mix/Boost、CC/CV 与生命周期状态组合成大量枚举值；也不让通信中断直接改变功率状态。

## 功率生命周期

RBT6 在 `system_sm.h` 中定义了 `BOOT(0)`、`HW_INIT(1)`、`PARAM_LOAD(2)`、`SELF_CHECK(3)`、`IDLE(4)`、`SOFT_START(5)`、`RUN(6)`、`STOPPING(7)`、`DIRECTION_SWITCH(8)`、`FAULT(9)`。当前 `SystemSm_Init()` 直接从 `SELF_CHECK` 开始；前三项是预留枚举，不是运行时已经走过的迁移。改变这些数值会改变 `UF4_ID_POWER_STATE` 的协议含义，必须同步检查上下位机。

| 当前状态               | 进入动作/保持条件                                                 | 允许迁移                                           |
|--------------------|-----------------------------------------------------------|------------------------------------------------|
| `SELF_CHECK`       | PWM 关闭；检查 ADC 电流/基准采样新鲜度、NTC、HRTIM 故障标志及当前检查路径覆盖的 COMP 信号 | 通过到 `IDLE`；进入本状态 1000 ms 后仍未通过则到 `FAULT`       |
| `IDLE`             | PWM 关闭；等待有效使能请求                                           | 请求使能且自检通过到 `SOFT_START`；自检失败到 `FAULT`          |
| `SOFT_START`       | 设置方向、复位调节器、允许运行；调节器逐步提升电压/电流目标                            | 停止或方向变化到 `STOPPING`；当前实现经过 750 ms 到 `RUN`      |
| `RUN`              | 维持闭环运行                                                    | 停止或方向变化到 `STOPPING`                            |
| `STOPPING`         | 先撤销运行许可并立即关 PWM；锁存待切换方向                                   | 至少等待 20 ms 后到 `DIRECTION_SWITCH` 或 `IDLE`      |
| `DIRECTION_SWITCH` | 只在输出关闭后修改方向并复位调节器                                         | 完成后到 `IDLE`，由下一轮重新判断是否启动                       |
| `FAULT`            | 锁存故障，撤销 PWM 运行许可并冗余关输出；ADC/DMA 保持运行                       | 清故障请求经历释放再置位、冷却至少 1000 ms 且自检通过后回 `SELF_CHECK` |

无论处于哪个非故障状态，检测到控制故障都应优先进入 `FAULT`。非法状态也应关输出并进入 `FAULT`。时间判断使用 `(uint32_t)(now - entered_ms) >= duration_ms`，以适应 tick 回绕。

## 调度与所有权

主循环按 `Uf4ComAdapter_Process()`、`CommandMailbox_Process()`、`SystemSm_Process()` 的顺序工作。每次状态机调用只读取一次 `power_command_t` 快照；先处理故障优先级，再按当前状态迁移，最后发布状态遥测。状态机是功率生命周期 `s_state`、进入时间和待切换方向的唯一写入者。每次迁移的输出使能/关闭、调节器复位、计时起点应集中在明确的进入动作中，避免状态值已变而硬件动作尚未完成。

HRTIM/COMP 硬件保护及故障中断必须能够不等待前台就关闭栅极并锁存原因；前台负责将其发布为 `FAULT`，决定是否允许清除。50 kHz 内环和 10 kHz 外环只消费运行许可、更新控制量或锁存故障，不修改高层生命周期。`PowerControl_ClearFault()` 只能从满足冷却、自检和清故障边沿条件的故障恢复路径调用；清除软件锁存与公开故障位时应审查中断竞争，避免新故障在清除过程中丢失。

ADC/DMA 在初始化后持续采样，不随 `IDLE`、`STOPPING` 或 `FAULT` 停止。故障时关闭的是功率级 PWM 输出和运行许可；采样、保护监测、通信与故障遥测继续工作，供定位故障和恢复前自检使用。不得把“采样持续运行”等同于“采样始终有效”：DMA 停滞或数据过期仍须被检测，且无有效采样时不能重新使能 PWM。

链路授权是使能的必要条件。RBT6 在通信超时 3000 ms 后撤销输出请求；状态机随后的前台调用执行停机。若必须保证更短的失联关断时延，应另行定义时限并验证最坏前台循环时间，而不是只依赖主循环通常很快。

## 独立状态与遥测

| 量 | 建议含义 | 注意事项 |
| --- | --- | --- |
| 功率生命周期 | `SELF_CHECK/IDLE/SOFT_START/RUN/STOPPING/DIRECTION_SWITCH/FAULT` 中恰好一个 | `UF4_ID_POWER_STATE (0x15)` 当前绑定 `g_uf4_power_state` |
| 故障原因 | 可同时出现的锁存位和首个故障原因 | `UF4_ID_FAULT_STATE (0x16)` 不应当作生命周期枚举 |
| 保护原始状态 | COMP 原始电平及 HRTIM FLT 使能位 | `UF4_ID_STATE_MACHINE_FLAG_BITS (0x17)` 当前绑定 `g_uf4_protection_status`；不是状态迁移事件或故障锁存 |
| 方向、拓扑、CC/CV | 与生命周期正交的当前值 | 分开发布，不生成组合状态 |
| 通信解析/链路、Flash 保存 | 各模块私有状态 | 不共享功率状态枚举 |

协议定义了 `UF4_ID_STATE_MACHINE_STATE (0x18)`，RBT6 当前遥测表未绑定该 ID；不要假定它与 `0x15` 等价。`power_telemetry.h` 中的 `DIGITAL_POWER_STATE_*`/`g_digital_power_status.state` 也不是当前高层状态的权威来源。后续应确定一个权威状态及固定协议编码，其他显示字段从它派生；废弃或实现未使用的 ID 前先确认现有上位机兼容性。

Flash 保存状态与功率状态分开。RBT6 当前生效的 v11 双快照流程使用 `snap_state`（空闲、等待擦除、写入后校验）；`parameter_manager.c` 中 `#if 0` 后的 `s_save_state` 是停用的 v9 journal，不能据此设计当前保存流程。

## 待确认的安全语义

1. **软启动完成：** 当前高层固定 750 ms 后进入 `RUN`，但调节器的 `ramp_v` 按 10 V/s 继续爬升，较高设定值远未达到目标。确定 `RUN` 是“闭环已获许可”还是“斜坡已完成”。若表示后者，完成判据应来自调节器的斜坡状态并考虑设定值运行中变化，而非固定延时。
2. **运行中采样失效：** ADC/DMA 正常情况下始终运行；这里专指 DMA 停滞或样本过期。当前快速环在 `current_valid == 0` 时关闭输出，慢环停止发布电流参考，但高层仍可能保持 `RUN`；采样恢复后会继续输出。明确允许短时跳脉冲的窗口、持续失效超时、恢复是否必须重新自检及软启动。即使选择进入 `FAULT`，也只关闭 PWM，不停 ADC/DMA。
3. **故障恢复再启动：** 目前清故障后回 `SELF_CHECK`。若上位机随后保持/重新发送使能，可能在检查通过后再次启动。明确是否必须观察一次新的“使能从 0 到 1”边沿；对短路等故障不宜仅凭仍保持的使能请求自动重试。
4. **停机窗口内命令变化：** 当前进入 `STOPPING` 时锁存目标方向，20 ms 后按该目标切换。定义窗口内撤销或再次改变请求的策略：完成原锁存动作后重新评估最新命令，或明确允许更新待切换方向；不能把两种语义混用。

以上是待决策的行为规范，不应把建议直接当成已验证的硬件行为。修改输出重启策略前，需在板上检查首次脉冲、HRTIM 故障锁存和换向死区。

## 实施与验证顺序

1. 固定协议数值与每个状态的含义，列出状态转换表、故障优先级、进入动作和超时；保留当前中断即时关断路径。
2. 明确上述四项安全语义，再对 `SystemSm_Process()` 做局部整理；不引入通用状态机库，也不把通信/存储状态合并进去。
3. 用可控 tick、命令、采样有效性和故障输入验证：启动自检失败、正常启动、750 ms 边界、运行中 ADC 中断/恢复、运行中故障、停机中换向与命令反复变化、失联、清故障边沿/冷却/再启动、tick 回绕。
4. 上板测量 PWM 关断时延、20 ms 换向死区、采样恢复首次脉冲及故障恢复条件；未完成上板测试前不宣称安全策略已验证。
