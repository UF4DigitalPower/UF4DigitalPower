# 控制代码详细说明

本文按照当前仓库中的实际代码说明 `E:\PROJECT_C\UF4DigitalPower` 的控制实现，重点对应以下文件：

- `Core/Src/main.c`
- `Core/Src/function.c`
- `Core/Inc/function.h`
- `Core/Src/pid.c`
- `Core/Inc/pid.h`
- `Core/Src/temp.c`

本文只描述“当前代码正在做什么”，不再沿用旧版 `power_ctrl` / `USER/CTRL` 架构的说法。

---

## 1. 项目当前控制结构

当前工程的控制逻辑比较集中，没有再拆成独立的 `BSP / CTRL / APP` 多层模块，而是主要由下面几部分组成：

1. `main.c`
   - 完成外设初始化
   - 启动 ADC、DMA、HRTIM、定时器中断
   - 在主循环里做慢速任务

2. `function.c`
   - 保存全局控制变量和状态变量
   - 完成 ADC 采样值滑动平均
   - 完成状态机
   - 完成保护逻辑
   - 完成 Buck / Boost / Mix 模式判定
   - 完成参数保存与风扇控制

3. `pid.c`
   - 完成电流环与电压环控制
   - 根据当前运行模式输出 Buck / Boost 占空比
   - 直接更新 HRTIM 比较寄存器

4. `temp.c`
   - 完成 NTC 温度和 MCU 温度换算

整体上，这是一个“中断驱动 + 全局变量共享”的控制工程。

---

## 2. 上电后的初始化流程

主入口在 `main()`。

上电后的关键流程如下：

1. `HAL_Init()` 和 `SystemClock_Config()`
2. 初始化 GPIO、DMA、ADC、HRTIM、SPI、TIM、USART、USB、CRC、FMAC
3. `DF.SMFlag = Init`，将主状态机置为初始化态
4. 启动风扇 PWM，先拉到 100%
5. 启动 `TIM6 / TIM7 / TIM16` 的定时中断
6. 调用 `PID_Init()`
7. 调用 `Init_Flash()` 和 `Read_Flash()` 读取参数
8. 延时 100 ms 等待供电稳定
9. 校准 ADC1、ADC2、ADC5
10. 启动 `ADC1 DMA`，并启动 `ADC2 / ADC3 / ADC5`
11. 启动 HRTIM Timer A、Timer D 计数器
12. 使能 HRTIM Timer A 的重复中断
13. 风扇占空比重新设为 0

可以把它理解成：

- `main.c` 负责把测量、控制和保护用到的底层资源都拉起来
- 真正的控制判断从定时器中断开始运行

## 3. 执行节拍

当前代码的执行节拍分成三层。

### 3.1 `TIM6` 1 ms 节拍

`HAL_TIM_PeriodElapsedCallback()` 里，`TIM6` 每 1 ms 执行一次，只做计数：

- `ms_cnt_1`
- `ms_cnt_2`
- `ms_cnt_3`
- `ms_cnt_4`

这些计数器在 `while(1)` 主循环中用于安排慢速任务。

### 3.2 `TIM7` 5 ms 节拍

`TIM7` 是当前控制逻辑的主调度节拍，每 5 ms 执行一次：

1. `ADCSample()`
2. `ShortOff()`
3. `OTP()`
4. `OVP()`
5. `OCP()`
6. `StateM()`
7. `BBMode()`

也就是说，采样平均、保护判定、主状态机推进、模式切换都在这个 5 ms 周期里完成。

### 3.3 主循环中的慢速任务

`while(1)` 中还有三类低速任务：

- 每 10 ms 执行 `ADC_calculate()`
  - 把平均 ADC 值换算成物理量
- 每 100 ms 执行 `Auto_FAN()`
  - 自动调风扇
- 每 500 ms 执行 `Update_Flash()`
  - 如果设置已修改，则写入外部 Flash

另外，主循环每 50 ms 会根据 `DF.SMFlag` 控制绿色 LED 的亮灭。

### 3.4 HRTIM 快环

`pid.c` 中的 `BuckBoostVILoopCtlPID()` 注释写明它应当在 HRTIM 中断中调用，用于执行快环控制并刷新 PWM 比较值。

当前 `stm32g4xx_it.c` 中只有 `HRTIM1_TIMA_IRQHandler()` 调用了 `HAL_HRTIM_IRQHandler()`，没有直接看到用户回调代码，因此实际快环调用位置应当在别的回调函数中，或者尚未补全到当前仓库版本。

## 4. 全局控制变量

当前控制主要依赖以下几组全局变量。

### 4.1 `CtrValue`

`struct _Ctr_value CtrValue`

主要包含：

- `Vout_ref`
  - 当前电压环参考值
- `Vout_SSref`
  - 软启动阶段允许达到的参考值
- `Vout_SETref`
  - 根据设置值换算得到的目标参考值
- `Iout_ref`
  - 输出电流参考值
- `BUCKMaxDuty`
  - Buck 允许的最大占空比
- `BoostMaxDuty`
  - Boost 允许的最大占空比
- `BuckDuty`
  - 当前 Buck 占空比命令
- `BoostDuty`
  - 当前 Boost 占空比命令

### 4.2 `DF`

`struct _FLAG DF`

主要包含：

- `SMFlag`
  - 主状态机状态
- `ErrFlag`
  - 故障标志位
- `BBFlag`
  - 当前 Buck / Boost / Mix 模式
- `PWMENFlag`
  - PWM 输出使能标志
- `BBModeChange`
  - 模式切换标志
- `OUTPUT_Flag`
  - 输出开关标志

### 4.3 `SADC`

`struct _ADI SADC`

保存输入输出电压、电流的瞬时 ADC 值和平均值：

- `Vin / VinAvg`
- `Iin / IinAvg`
- `Vout / VoutAvg`
- `Iout / IoutAvg`

### 4.4 设置量与测量量

- `SET_Value`
  - 输出电压、电流及设置修改标志
- `VIN / VOUT / IIN / IOUT`
  - 当前换算后的物理量
- `Board1_TEMP / Board2_TEMP / CPU_TEMP`
  - 当前温度值

## 5. ADC 采样与物理量换算

### 5.1 ADC1 DMA 采样内容

`ADC1_RESULT[4]` 由 `HAL_ADC_Start_DMA(&hadc1, ADC1_RESULT, 4)` 持续更新，当前四路含义为：

- `ADC1_RESULT[0]` -> `Vin`
- `ADC1_RESULT[1]` -> `Iin`
- `ADC1_RESULT[2]` -> `Vout`
- `ADC1_RESULT[3]` -> `Iout`

### 5.2 `ADCSample()` 的处理方式

`ADCSample()` 在 5 ms 中断里执行，主要做三件事：

1. 从 DMA 缓冲区拿最新值
2. 对 `Vout` 和 `Iout` 做一次线性校正
3. 对四路数据做滑动平均

其中：

- `Vout` 校正使用 `CAL_VOUT_K` 和 `CAL_VOUT_B`
- `Iout` 校正使用 `CAL_IOUT_K` 和 `CAL_IOUT_B`
- `Vin/Vout/Iout` 小于一个很小阈值时直接清零，抑制零点抖动

平均算法不是“存数组求平均”，而是这种一阶近似滑动平均：

```text
sum = sum + sample - (sum >> 3)
avg = sum >> 3
```

因此平均窗口大约等效于 8 点。

### 5.3 电压换算

`ADC_calculate()` 每 10 ms 执行一次，把平均值换成实际电压：

```text
VIN  = VinAvg  * REF_3V3 / ADC_MAX_VALUE * BSP_POWER_VIN_SENSE_SCALE
VOUT = VoutAvg * REF_3V3 / ADC_MAX_VALUE * BSP_POWER_VOUT_SENSE_SCALE
```

这里：

- `REF_3V3 = 3.2806`
- 电压采样分压比由 `75000 / 5000` 定义
- 当前宏 `BSP_POWER_DIVIDER_SCALE(r_upper, r_lower)` 直接写成 `r_upper / r_lower`

所以当前代码按 15 倍进行电压还原。

### 5.4 电流换算

当前代码的电流换算公式为：

```text
I = (adc_voltage - 1.65V) / (0.007 * 20)
```

也就是：

- 检流电阻 `7 mOhm`
- 运放增益 `20`
- 中点偏置 `1.65V`

换算后：

- 输入电流来自 `SADC.IinAvg`
- 输出电流来自 `SADC.IoutAvg`

需要注意的是，当前 `ADC_calculate()` 对 `IIN/IOUT` 使用的是 `adc_voltage - bias`，这会让电流方向定义与早期文档里的“偏置以下为正电流”表述不完全一致。文档应以当前公式为准。

### 5.5 温度换算

`temp.c` 提供了三类温度读取：

- `GET_NTC1_Temperature()`
- `GET_NTC2_Temperature()`
- `GET_CPU_Temperature()`

其中：

1. NTC 温度通过 B 值公式换算
2. 温度范围被限制在 `-40°C ~ 120°C`
3. CPU 温度结果会再经过一次一阶低通滤波

## 6. 主状态机

主状态机由 `DF.SMFlag` 表示，共有五种状态：

- `Init`
- `Wait`
- `Rise`
- `Run`
- `Err`

状态机入口函数是 `StateM()`，每 5 ms 调用一次。

### 6.1 `Init`

对应函数 `StateMInit()`。

它只做两件事：

1. 调用 `ValInit()`
2. 把状态切到 `Wait`

### 6.2 `ValInit()`

这是整个控制变量的集中初始化入口，主要动作有：

- 关闭 PWM
- 停止 Buck 和 Boost HRTIM 输出
- `DF.BBFlag = NA`
- `DF.ErrFlag = 0`
- 清空电压环历史量 `VErr0/1/2`
- 清空电压环输出量 `u0/u1`
- 初始化占空比上下限
- 把设置值恢复为默认值：
  - `Vout = 5.0V`
  - `Iout = 1.0A`
  - `OTP = 80°C`
  - `OVP = 45V`
  - `OCP = 10A`

注意：这些默认值随后可能会被 `Read_Flash()` 读回的历史参数覆盖。

### 6.3 `Wait`

对应函数 `StateMWait()`。

当前逻辑是：

- 始终关闭 PWM
- 每 5 ms 计数一次
- 累计超过 200 次后，相当于等待约 1 s
- 若此时：
  - `DF.ErrFlag == F_NOERR`
  - `DF.OUTPUT_Flag == 1`
- 则进入 `Rise`

进入 `Rise` 前会清零软启动相关计数，并把软启动子状态 `STState` 设为 `SSInit`。

### 6.4 `Rise`

对应函数 `StateMRise()`。

软启动又细分为三个子状态：

- `SSInit`
- `SSWait`
- `SSRun`

#### `SSInit`

主要动作：

- 关闭 PWM
- 清空环路历史量
- 将最大占空比都限制在最小值
- 把用户设置值换算成 ADC 参考量：
  - `CtrValue.Vout_SETref`
  - `CtrValue.Iout_ref`
- 转入 `SSWait`

其中参考值换算方式为：

- 电压参考按电压采样链反推到 ADC 码值
- 电流参考按 `1.65V + I * Rsense * Gain` 反推到 ADC 码值

#### `SSWait`

作用是软启动前的短等待窗口。

- 每 5 ms 计数一次
- 超过 5 次后，大约等待 25 ms
- 然后：
  - 重新把占空比上限压回最小值
  - 再次清零环路历史量
  - 把 `Vout_SSref` 设为 `Vout_SETref >> 1`

也就是说，软启动初期只允许先爬到目标电压的一半。

#### `SSRun`

这是实际的软启动执行阶段。

第一次进入时：

- 若 `PWMENFlag == 0`
- 先清零环路变量
- 把 HRTIM 比较值打到全周期
- 启动 Buck 和 Boost PWM 输出

之后每 5 ms：

- `PWMENFlag = 1`
- `BUCKMaxDutyCnt` 和 `BoostMaxDutyCnt` 递增
- `BUCKMaxDuty` 和 `BoostMaxDuty` 逐步放宽
- 每次按 `计数 * 15` 的增量继续推高
- 达到各自最大值后钳住

当 Buck 和 Boost 的最大允许占空比都放宽到上限后：

- `DF.SMFlag = Run`
- `STState = SSInit`

### 6.5 `Run`

对应函数 `StateMRun()`。

当前版本中这个函数是空的：

```c
void StateMRun(void){}
```

也就是说，正常运行态本身没有在这里再做额外调度，实际闭环控制主要依赖快环函数 `BuckBoostVILoopCtlPID()`。

### 6.6 `Err`

对应函数 `StateMErr()`。

故障状态下的动作：

- 关闭 PWM
- 停止 Buck 和 Boost 输出
- 红灯亮，绿灯灭，黄灯灭
- `DF.BBFlag = NA`

如果后续 `DF.ErrFlag == F_NOERR`，则：

- 状态切回 `Wait`
- 红灯灭，绿灯亮

也就是说，故障恢复是否能回到等待态，取决于各类保护函数是否清除了相应故障位。

## 7. Buck / Boost / Mix 模式判定

模式判定函数是 `BBMode()`，每 5 ms 执行一次。

### 7.1 判定依据

它不是直接用实际伏特值，而是用：

- `CtrValue.Vout_ref`
- `VIN_ADC`

也就是“输出参考 ADC 值”和“输入电压 ADC 值”的相对关系来判断模式。

### 7.2 输入电压平均

`VIN_ADC` 会用 5 次采样做一次简单平均，减小临界点抖动。

### 7.3 模式切换门限

当前代码中门限如下。

#### `NA` 状态进入模式

- `Vout_ref < 0.8 * Vin` -> `Buck`
- `Vout_ref > 1.2 * Vin` -> `Boost`
- 其余 -> `Mix`

#### `Buck` 状态

- `Vout_ref > 1.2 * Vin` -> `Boost`
- `Vout_ref > 0.85 * Vin` -> `Mix`

#### `Boost` 状态

- `Vout_ref < 0.8 * Vin` -> `Buck`
- `Vout_ref < 1.15 * Vin` -> `Mix`

#### `Mix` 状态

- `Vout_ref < 0.8 * Vin` -> `Buck`
- `Vout_ref > 1.2 * Vin` -> `Boost`

这说明当前代码已经加入了迟滞：

- `Buck -> Mix` 用 `0.85`
- `Boost -> Mix` 用 `1.15`
- `Mix -> Buck/Boost` 用 `0.8 / 1.2`

### 7.4 模式切换标志

如果本次模式和上次模式不同：

- `DF.BBModeChange = 1`

否则：

- `DF.BBModeChange = 0`

这个标志会被快环函数用来在模式切换时清空部分环路状态，减小过冲。

## 8. 双环控制与 PWM 输出

控制核心函数是 `BuckBoostVILoopCtlPID()`。

### 8.1 控制总体思路

当前实现是典型“双环串级”：

1. 电流环先根据 `Iout_ref` 和 `IoutTemp` 算出一个修正量 `i0`
2. 用 `i0` 去修正 `Vout_ref`
3. 再由电压环根据 `Vout_ref - VoutTemp` 算出最终 PWM 命令

也就是说，代码虽然命名为“电压环 + 电流环”，但实现方式是：

- 电流环调节电压参考
- 电压环输出占空比

### 8.2 电流环

当前电流环变量：

- 误差：`IErr0`
- 积分量：`I_Integral`
- 输出：`i0`

公式：

```text
IErr0 = Iout_ref - IoutTemp
i0 = I_Integral + IErr0 * KP + (IErr0 - IErr1) * KD
I_Integral = I_Integral + IErr0 * KI
```

参数定义在 `pid.h`：

- `ILOOP_KP = 6`
- `ILOOP_KI = 3`
- `ILOOP_KD = 1`

积分量只做了上限限制：

- `I_Integral <= ADC_MAX_VALUE`

当前代码没有看到对应的负向下限限制。

### 8.3 电压参考的生成

函数一开始会先把：

```text
Vout_ref = Vout_SETref
```

然后再加上电流环输出 `i0`。

#### 软启动阶段

若：

- `DF.SMFlag == Rise`
- 且 `VoutTemp < Vout_ref / 2`

则电压参考上限被限制为 `Vout_SSref`，也就是设置值的一半。

#### 正常阶段

否则电压参考上限被限制为 `Vout_SETref`。

并且：

- 超过上限时切回 `CV`
- 未超过时标为 `CC`
- 小于 0 时钳到 0

当前 `CVCC_Mode` 因此反映了“电流环是否顶住了电压参考上限”。

### 8.4 模式切换时的处理

如果 `DF.BBModeChange == 1`：

- `u1 = 0`
- `I_Integral = 0`
- `i0 = 0`
- `DF.BBModeChange = 0`

也就是在模式切换时清空部分历史量，避免 Buck / Boost / Mix 切换后直接带着旧模式积分继续跑。

### 8.5 电压环离散系数

`pid.h` 中定义了两组电压环系数。

Buck：

- `BUCKPIDb0 = 5795`
- `BUCKPIDb1 = -11411`
- `BUCKPIDb2 = 5617`

Boost：

- `BOOSTPIDb0 = 8844`
- `BOOSTPIDb1 = -17413`
- `BOOSTPIDb2 = 8572`

电压环实现形式为：

```text
u0 = u1 + e[k]*b0 + e[k-1]*b1 + e[k-2]*b2
```

这是一个离散补偿器形式，不是传统位置式 PID 直接写法。

### 8.6 三种模式下的占空比分配

#### `NA`

直接清零环路历史状态，不输出有效控制。

#### `Buck`

- `BoostDuty = BSP_POWER_BOOST_DUTY_MIN_TICK`
- `BuckDuty = (u0 >> 8) * 3`
- `BuckDuty` 限制在：
  - 下限 `BSP_POWER_BUCK_DUTY_MIN_TICK`
  - 上限 `CtrValue.BUCKMaxDuty`

#### `Boost`

- `BuckDuty = BSP_POWER_BUCK_DUTY_MAX_TICK`
- `BoostDuty = (u0 >> 8) * 3`
- `BoostDuty` 限制在：
  - 上限 `CtrValue.BoostMaxDuty`
  - 下限代码当前写成 `BSP_POWER_BOOST_DUTY_MAX_TICK`

#### `Mix`

- `BuckDuty = BSP_POWER_BUCK_DUTY_SYNC_MAX_TICK`
- `BoostDuty = (u0 >> 8) * 3`
- `BoostDuty` 限制逻辑与 `Boost` 类似

### 8.7 PWM 输出更新

最后函数会直接更新 HRTIM 比较寄存器：

1. `Timer A Compare1`
   - 作为 Buck 占空比
2. `Timer A Compare3`
   - 作为 ADC 触发点，位置在 Buck 比较值的一半
3. `Timer D Compare1`
   - 作为 Boost 占空比

其中 Buck 比较值写入方式是：

```text
Period - BuckDuty
```

说明当前 PWM 极性和比较方式是按现有 HRTIM 配置来的，不宜只看公式字面理解为“数值越大占空比越大”。

## 9. 保护逻辑

当前保护函数都在 `TIM7` 的 5 ms 节拍里执行。

### 9.1 短路保护 `ShortOff()`

判据：

- `Iout > POWER_CTRL_SHORT_CURRENT`
- 且 `Vout < POWER_CTRL_SHORT_VOLTAGE`

默认阈值：

- 短路电流 `10.0A`
- 短路电压 `0.5V`

触发后：

- `PWMENFlag = 0`
- 置位 `F_SW_SHORT`
- `DF.SMFlag = Err`

恢复逻辑：

- 故障后每 5 ms 计一次
- 超过 400 次，大约 2 s
- 最多尝试自动恢复 10 次
- 超过次数后保持故障不清除

### 9.2 输出过压保护 `OVP()`

判据：

- `Vout >= MAX_VOUT_OVP_VAL`

默认阈值：

- `45V`

保持计时：

- `OVPCnt > 2`
- 以 5 ms 节拍算，大约 10 ms

触发后：

- 关闭 PWM
- 停止 Buck / Boost 输出
- 置位 `F_SW_VOUT_OVP`
- 状态切到 `Err`

### 9.3 输出过流保护 `OCP()`

判据：

- `Iout >= MAX_VOUT_OCP_VAL`
- 且 `DF.SMFlag == Run`

默认阈值：

- `10A`

保持计时：

- `OCPCnt > 10`
- 以 5 ms 节拍算，大约 50 ms

触发后：

- 关闭 PWM
- 置位 `F_SW_IOUT_OCP`
- 状态切到 `Err`

恢复逻辑：

- 每约 2 s 尝试一次恢复
- 最多恢复 10 次
- 超过次数后保持故障

### 9.4 过温保护 `OTP()`

判据：

- `NTC1 >= MAX_OTP_VAL`
- 或 `NTC2 >= MAX_OTP_VAL`

默认阈值：

- `80°C`

触发后：

- 关闭 PWM
- 停止 Buck / Boost 输出
- 置位 `F_OTP`
- 状态切到 `Err`

### 9.5 故障标志位

当前故障位定义如下：

- `F_SW_VIN_UVP`
- `F_SW_VIN_OVP`
- `F_SW_VOUT_UVP`
- `F_SW_VOUT_OVP`
- `F_SW_IOUT_OCP`
- `F_SW_SHORT`
- `F_OTP`

其中当前代码里真正用到的主要是：

- `F_SW_VOUT_OVP`
- `F_SW_IOUT_OCP`
- `F_SW_SHORT`
- `F_OTP`

`VIN_UVP / VIN_OVP / VOUT_UVP` 目前只定义了宏，还没有看到对应的实际保护逻辑实现。

## 10. 参数存储

当前参数存储使用外部 `W25Q64`。

### 10.1 初始化

`Init_Flash()` 会先读取地址 `0x000000` 的标志位：

- 若不是 `0x00`
- 则擦除扇区并写入默认参数

写入的内容总共 21 字节：

1. 1 字节标志位
2. `Vout`
3. `Iout`
4. `OTP`
5. `OCP`
6. `OVP`

后面五项都是按 `float` 的 4 字节原样保存。

### 10.2 读取

`Read_Flash()` 从 `0x000001` 开始读取 20 字节，然后恢复：

- `SET_Value.Vout`
- `SET_Value.Iout`
- `MAX_OTP_VAL`
- `MAX_VOUT_OCP_VAL`
- `MAX_VOUT_OVP_VAL`

### 10.3 更新

`Update_Flash()` 只有在：

- `SET_Value.SET_modified_flag == 1`

时才会执行擦除和重写，然后把修改标志清零。

当前它由主循环每 500 ms 调用一次。

## 11. 风扇控制

### 11.1 手动设定

`FAN_PWM_set(uint16_t dutyCycle)`：

- 输入范围按 `0 ~ 100`
- 超过 100 会被钳住
- 实际写入 `TIM8 CH3`
- 比较值为 `dutyCycle * 10`

### 11.2 自动风扇

`Auto_FAN()` 每 100 ms 调用一次。

它会用两个板温加权平均：

```text
TEMP = TEMP1 * 0.6 + TEMP2 * 0.4
```

然后按分段条件给风扇占空比。

需要注意，当前代码分支顺序是：

```c
if (TEMP < 35) ...
else if (TEMP >= 35) ...
else if (TEMP >= 40) ...
```

由于 `TEMP >= 35` 已经把更高温区间全部覆盖，后面的 `40 / 45 / 50 / 55 / 60 / 65` 分支实际上不会被执行。

所以按当前代码真实行为：

- `TEMP < 35` -> 风扇 0%
- `TEMP >= 35` -> 风扇 35%

文档应当以这个“当前实际行为”为准，而不是按原意去写成多段调速。

## 12. LED 指示

当前代码里的 LED 逻辑有两层。

### 12.1 主循环绿色 LED

主循环每 50 ms 判断：

- 若状态是 `Rise` 或 `Run`
  - 绿灯亮
- 否则
  - 绿灯灭

### 12.2 故障态 LED

`StateMErr()` 中直接控制：

- 红灯亮
- 绿灯灭
- 黄灯灭

如果故障恢复并回到 `Wait`：

- 红灯灭
- 绿灯亮
- 黄灯灭

## 13. 当前代码中需要特别注意的实现现状

下面这些不是未来设计目标，而是当前仓库版本里已经存在、写文档时必须说明清楚的地方。

### 13.1 `Run` 状态为空

当前 `StateMRun()` 没有内容，正常运行态的主要控制不在这个函数里完成，而是依赖快环控制函数。

### 13.2 文档与旧架构已脱节

仓库里旧文档中提到的：

- `power_ctrl.c/h`
- `bsp_power.c/h`
- `USER/CTRL`
- `snapshot/settings` 风格接口

已经不是当前代码结构，不能再作为现版本说明。

### 13.3 HRTIM 快环回调链路需要结合实际工程再确认

当前可以确认：

- HRTIM Timer A 中断已使能
- `BuckBoostVILoopCtlPID()` 设计上就是快环入口

但从现有 `stm32g4xx_it.c` 还看不到完整用户回调调用链，调试时需要再结合 HRTIM HAL 回调或其他文件确认。

### 13.4 若干保护函数里的 PWM Start/Stop 写法存在不一致

例如：

- `ShortOff()` 触发故障后调用了 `WaveformOutputStart()`
- `OCP()` 中 Boost 输出停止用的是 `TF1/TF2`
- 其他地方多为 `TD1/TD2`

这说明当前代码里还存在一些需要进一步核实的实现细节。本文档只记录现状，不替代码做推断修正。

### 13.5 风扇自动调速分支存在覆盖问题

`Auto_FAN()` 目前实际只会输出两个档位：

- 0%
- 35%

这不是文档推断，而是由当前 `else if` 顺序直接决定的。

## 14. 当前代码的一句话总结

当前版本是一个以 `TIM7 5ms` 为慢速调度、以 `HRTIM` 为快环执行基础的数字电源控制程序：

- `ADCSample()` 完成输入输出采样平均
- `StateM()` 管理 `Init -> Wait -> Rise -> Run -> Err`
- `BBMode()` 在 Buck / Boost / Mix 之间切换
- `BuckBoostVILoopCtlPID()` 完成电流环、电压环和 PWM 输出
- `OTP / OVP / OCP / ShortOff` 完成基础保护
- `Init_Flash / Read_Flash / Update_Flash` 完成参数保存与恢复

如果后续代码继续演进，建议优先同步更新本文档中的以下章节：

- 执行节拍
- 状态机
- 模式切换门限
- PID 系数与输出分配
- 保护恢复策略
