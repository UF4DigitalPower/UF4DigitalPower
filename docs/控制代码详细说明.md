# 控制代码详细说明

本文详细说明 `E:\PROJECT_C\UF4DigitalPower` 当前控制代码的结构、数据流、状态机、采样换算、保护逻辑和双环控制实现。重点覆盖以下文件：

- `USER/CTRL/power_ctrl.h`
- `USER/CTRL/power_ctrl.c`
- `USER/BSP/bsp_power.h`
- `USER/BSP/bsp_power.c`

本文目标不是只解释“这段代码在做什么”，而是把“为什么这样组织、每个量代表什么、执行顺序是什么、调试时该看哪些变量”都讲清楚。

---

## 1. 总体架构

当前工程的控制层可以分成两层：

1. `BSP` 层
   - 负责 ADC 原始值读取
   - 负责把原始 ADC 值换算成 `Vin / Vout / Iin / Iout / 温度`
   - 负责提供和硬件量纲一致的基础接口

2. `CTRL` 层
   - 负责状态机
   - 负责模式判定：`BUCK / BOOST / MIX`
   - 负责保护逻辑
   - 负责软启动
   - 负责双环控制：
     - 电压外环输出电流参考 `Iref`
     - 电流内环输出 PWM 占空比 `Duty`

代码入口是：

```c
void POWER_runAppControlTick(void)
```

它由 HRTIM 中断或等效快节拍周期调用，是整个控制系统的主入口。

## 3. 硬件抽象与量纲

控制代码内部大量使用的是“ADC raw”，不是直接使用伏特和安培。这是为了减少浮点参与快环计算的次数。

### 3.1 ADC 满量程定义

在 `bsp_power.h` 中：

```c
#define BSP_POWER_ADC1_FULL_SCALE_RAW        4095.0F
#define BSP_POWER_ADC_VREF_V                 3.2806F
```

这表示控制相关的主 ADC 量程按 `4095` raw 对应 `3.2806V`。

### 3.2 电压分压

```c
#define BSP_POWER_VIN_R_UPPER_OHM            75000.0F
#define BSP_POWER_VIN_R_LOWER_OHM            5000.0F
#define BSP_POWER_VOUT_R_UPPER_OHM           75000.0F
#define BSP_POWER_VOUT_R_LOWER_OHM           5000.0F
```

因此：

- `Vin` 缩小 15 倍送 ADC
- `Vout` 也缩小 15 倍送 ADC

对应换算：

```c
float BSP_getAppVinVoltage(uint16_t raw)
{
    return BSP_getAppAdc1Voltage(raw) * BSP_POWER_VIN_SENSE_SCALE;
}
```

```c
float BSP_getAppVoutVoltage(uint16_t raw)
{
    return BSP_getAppAdc1Voltage(raw) * BSP_POWER_VOUT_SENSE_SCALE;
}
```

### 3.3 电流采样

```c
#define BSP_POWER_CURRENT_SHUNT_OHM          0.007F
#define BSP_POWER_CURRENT_AMP_GAIN           20.0F
#define BSP_POWER_CURRENT_BIAS_V             1.650F
#define BSP_POWER_CURRENT_SENSE_V_PER_A      (BSP_POWER_CURRENT_SHUNT_OHM * BSP_POWER_CURRENT_AMP_GAIN)
```

这里的关键思想是：

- 电流采样有 `1.65V` 偏置
- 电流越大，ADC 电压从 `1.65V` 向下掉
- 若采样电压高于偏置，认为是反向电流或无效，直接裁成 `0A`

对应实现：

```c
static float s_BSP_getAppCurrentFromRaw(uint16_t raw, float scale)
{
    const float sense_voltage = BSP_getAppAdc1Voltage(raw);

    if (sense_voltage >= BSP_POWER_CURRENT_BIAS_V)
    {
        return 0.0F;
    }

    return ((BSP_POWER_CURRENT_BIAS_V - sense_voltage) / BSP_POWER_CURRENT_SENSE_V_PER_A) * scale;
}
```

这段逻辑非常重要，因为它决定了控制代码里“正向电流”的定义。

## 4. 控制模式定义

代码把工作模式分成三种：

```c
typedef enum
{
    POWER_CTRL_STAGE_NA = 0U,
    POWER_CTRL_STAGE_BUCK = 1U,
    POWER_CTRL_STAGE_BOOST = 2U,
    POWER_CTRL_STAGE_MIX = 3U,
} POWER_ctrlStage_t;
```

含义如下：

- `NA`
  - 当前不可控
  - 常见于掉压、未启动、故障状态

- `BUCK`
  - 输出参考明显低于输入
  - 主调制桥臂使用 Buck 侧逻辑
  - 电流内环使用 `IOUT`

- `BOOST`
  - 输出参考明显高于输入
  - 主调制桥臂使用 Boost 侧逻辑
  - 电流内环使用 `IIN`

- `MIX`
  - 输入输出接近
  - 用于模式过渡区
  - 当前实现里仍然更接近 Boost 方式来控制

- `pwm_d_compare`
  - HRTIM D 的比较值

这几个量基本能让你看清当前控制系统“脑子里在想什么”。

## 6. 控制频率与调度

代码中定义了三个频率概念：

```c
#define POWER_CTRL_FAST_LOOP_HZ                 200000U
#define POWER_CTRL_VOLTAGE_LOOP_HZ              1000U
#define POWER_CTRL_SLOW_LOOP_HZ                 200U
```

对应含义：

- `200kHz`
  - 快速控制周期
  - 每个 PWM 周期执行一次
  - 主要跑电流内环

- `1kHz`
  - 电压外环周期
  - 每 200 次快环执行一次
  - 负责根据电压误差更新电流参考

- `200Hz`
  - 慢环/后台管理周期
  - 每 1000 次快环执行一次
  - 负责：
    - ADC 平滑
    - UVLO/保护
    - 故障恢复
    - 状态机
    - 模式更新
    - 风扇
    - 指示灯

### 6.1 主循环入口

```c
void POWER_runAppControlTick(void)
{
    BSP_getAppAdcResult(&s_POWER_fastAdcResult);

    ++s_POWER_voltageLoopDivider;
    if (s_POWER_voltageLoopDivider >= POWER_CTRL_VOLTAGE_LOOP_DIVIDER)
    {
        s_POWER_voltageLoopDivider = 0U;
        s_POWER_runAppVoltageLoop();
    }

    ++s_POWER_slowLoopDivider;
    if (s_POWER_slowLoopDivider >= POWER_CTRL_SLOW_LOOP_DIVIDER)
    {
        s_POWER_slowLoopDivider = 0U;
        s_POWER_sampleAppAdc();
        s_POWER_updateAppVinUvLock();
        s_POWER_checkAppProtection();
        s_POWER_updateAppFaultRecovery();
        s_POWER_handleAppState();
        s_POWER_updateAppMode();
        s_POWER_updateAppFan();
        s_POWER_updateAppStatusLed();
    }

    s_POWER_runAppPid();
}
```

执行顺序非常明确：

1. 先拿到最新快速 ADC 结果
2. 如果到 `1kHz` 节拍，执行电压外环
3. 如果到 `200Hz` 节拍，执行慢速管理逻辑
4. 每次都执行快速电流内环

## 7. 数据结构详解

### 7.1 `POWER_controlValue_t`

这是控制系统的核心运行结构：

```c
typedef struct
{
    int32_t vout_ref_raw;
    int32_t vout_softstart_ref_raw;
    int32_t vout_set_ref_raw;
    int32_t iout_limit_raw;
    int32_t iout_ref_raw;
    int16_t buck_max_duty_tick;
    int16_t boost_max_duty_tick;
    int16_t buck_duty_tick;
    int16_t boost_duty_tick;
    int32_t current_loop_out;
} POWER_controlValue_t;
```

字段含义：

- `vout_set_ref_raw`
  - 用户设置的目标输出电压，转换成 raw 后的值

- `vout_softstart_ref_raw`
  - 软启动时用的中间电压参考

- `vout_ref_raw`
  - 当前电压外环真正使用的参考值
  - 在软启动阶段可能小于目标值

- `iout_limit_raw`
  - 用户设置的最大输出电流上限，raw 形式

- `iout_ref_raw`
  - 电压外环输出给电流内环的“实际电流参考”
  - 这是当前双环结构的关键变量

- `buck_max_duty_tick`
  - 软启动阶段对 Buck 占空比的限制

- `boost_max_duty_tick`
  - 软启动阶段对 Boost 占空比的限制

- `buck_duty_tick`
  - 当前输出给 Buck 桥臂的 duty

- `boost_duty_tick`
  - 当前输出给 Boost 桥臂的 duty

- `current_loop_out`
  - 当前内环控制器输出值

### 7.2 `POWER_sample_t`

```c
typedef struct
{
    uint16_t vin_raw_avg;
    uint16_t iin_raw_avg;
    uint16_t vout_raw_avg;
    uint16_t iout_raw_avg;
    BSP_powerMeasurement_t measurement;
} POWER_sample_t;
```

作用：

- 保存慢速平均后的 ADC 结果
- 保存换算后的物理量
- 给保护、模式判定、风扇和快照使用

## 8. ADC 采样与滤波

### 8.1 快速 ADC

快环每次直接读取：

```c
BSP_getAppAdcResult(&s_POWER_fastAdcResult);
```

这份数据给快速控制环使用，追求快响应。

### 8.2 慢速平均

`s_POWER_sampleAppAdc()` 中用了一个一阶 IIR 平滑：

```c
vin_avg_sum = vin_avg_sum + adc_result.vin_raw - (vin_avg_sum >> 3);
```

这等价于近似 `1/8` 的低通平滑。

效果：

- 快环继续用快数据
- 慢速管理逻辑用更稳的数据
- 保护和模式切换不容易被瞬态噪声误触发

这是一个很合理的架构分离。

## 9. 模式切换逻辑

模式切换由 `s_POWER_updateAppMode()` 完成。

### 9.1 判定依据

判定核心是 `vout_ref_raw` 与 `vin_raw` 的比值关系，而不是直接用当前测量输出值。

这表示模式判定更偏向“目标工作区”而不是“瞬时扰动值”。

### 9.2 阈值策略

核心阈值：

- `< 0.8 * Vin` 进入 `BUCK`
- `> 1.2 * Vin` 进入 `BOOST`
- 中间区间进入或保持 `MIX`

带迟滞的逻辑：

- `BUCK -> MIX` 使用 `0.85 * Vin`
- `BOOST -> MIX` 使用 `1.15 * Vin`

这样做的目的是避免在边界附近来回抖动。

### 9.3 模式变化后的处理

模式变化会置位：

```c
s_POWER_stageModeChanged = 1
```

然后在 `s_POWER_runAppPid()` 里执行：

```c
if (s_POWER_stageModeChanged != 0U)
{
    s_POWER_resetAppPid();
    s_POWER_stageModeChanged = 0U;
}
```

这一步非常关键，因为不同模式下：

- 采样对象不同
- duty 作用对象不同
- 控制器积分状态不能直接继承

如果不清状态，切换时很容易出现瞬态冲击。

## 10. 双环控制结构

这是当前代码最核心的部分。

### 10.1 当前结构

当前代码已经是双环：

- 外环：电压环
  - 输入：`Vref - Vout`
  - 输出：`Iref`

- 内环：电流环
  - 输入：`Iref - Imeas`
  - 输出：`Duty`

也就是：

```text
Vref - Vout -> Voltage PID -> Iref
Iref - Imeas -> Current PI(D) -> Duty
```

### 10.2 为什么这样更合理

相比之前“电压环直接出 duty，电流环只做限流修正”的结构，双环有这些优点：

- 电压环和电流环职责更清楚
- 内环带宽更高，可以更快压住电流变化
- 外环只需要调节目标电流，抗扰动更稳
- 更容易做恒流限流和 CV/CC 切换

## 11. 电压外环详解

### 11.1 执行频率

电压外环在 `1kHz` 执行。

### 11.2 参考电压选择

```c
static int32_t s_POWER_getAppActiveVoutLimitRaw(int32_t vout_raw)
```

它的作用是决定当前外环使用哪个电压参考。

逻辑：

- 正常运行：使用 `vout_set_ref_raw`
- 软启动阶段：在输出电压还没到目标一半前，先用 `vout_softstart_ref_raw`

这能避免一上电就把外环目标拉太高。

### 11.3 电压环实现

核心函数：

```c
static void s_POWER_runAppVoltageLoop(void)
```

主要流程：

1. 计算当前电压参考 `vout_ref_raw`
2. 根据模式选择 Buck 或 Boost 的电压 PID 系数
3. 用增量式 PID 更新 `s_POWER_u0`
4. 将 `s_POWER_u0` 右移缩放成 `iout_ref_raw`
5. 用 `iout_limit_raw` 限流
6. 决定当前是 `CV` 还是 `CC`

### 11.4 增量式 PID

Buck：

```c
s_POWER_u0 = s_POWER_u1 +
             (s_POWER_v_err0 * POWER_CTRL_BUCK_PID_B0) +
             (s_POWER_v_err1 * POWER_CTRL_BUCK_PID_B1) +
             (s_POWER_v_err2 * POWER_CTRL_BUCK_PID_B2);
```

Boost/Mix：

```c
s_POWER_u0 = s_POWER_u1 +
             (s_POWER_v_err0 * POWER_CTRL_BOOST_PID_B0) +
             (s_POWER_v_err1 * POWER_CTRL_BOOST_PID_B1) +
             (s_POWER_v_err2 * POWER_CTRL_BOOST_PID_B2);
```

这是一种标准增量式离散 PID 形式：

```text
u[k] = u[k-1] + b0*e[k] + b1*e[k-1] + b2*e[k-2]
```

### 11.5 输出缩放

```c
current_ref_raw = s_POWER_u0 >> POWER_CTRL_VOLTAGE_LOOP_TO_CURRENT_SHIFT;
```

这里的 `>> 9` 不是理论公式里的固定参数，而是工程缩放系数。

作用：

- 把电压环输出数值缩放到合适的电流参考量级
- 避免 `iout_ref_raw` 太大或太小

这部分后续还可以继续细调。

### 11.6 CV / CC 判定

默认先认为当前是 `CV`：

```c
s_POWER_ctrlCvccMode = POWER_CTRL_CVCC_CV;
```

如果电压环给出的 `current_ref_raw` 超过了用户设定的 `iout_limit_raw`，就裁到上限，并切到 `CC`：

```c
if (current_ref_raw >= s_POWER_controlValue.iout_limit_raw)
{
    current_ref_raw = s_POWER_controlValue.iout_limit_raw;
    s_POWER_ctrlCvccMode = POWER_CTRL_CVCC_CC;
}
```

这就是当前系统里 `CV/CC` 的本质实现。

## 12. 电流内环详解

### 12.1 执行频率

电流内环每次 `POWER_runAppControlTick()` 都执行一次，也就是 `200kHz`。

### 12.2 电流反馈选择

由：

```c
static uint16_t s_POWER_getAppInnerCurrentRaw(const BSP_adcResult_t *adc_result, uint8_t stage_mode)
```

决定。

逻辑：

- `BUCK` 模式：用 `IOUT`
- `BOOST / MIX` 模式：用 `IIN`

这和功率流方向一致：

- Buck 时电感电流更接近输出侧电流
- Boost 时电感电流更接近输入侧电流

### 12.3 当前内环控制律

```c
s_POWER_i0 = s_POWER_currentIntegral +
             (s_POWER_i_err0 * POWER_CTRL_CURRENT_LOOP_KP) +
             ((s_POWER_i_err0 - s_POWER_i_err1) * POWER_CTRL_CURRENT_LOOP_KD);
```

同时积分项独立累计：

```c
s_POWER_currentIntegral += s_POWER_i_err0 * POWER_CTRL_CURRENT_LOOP_KI;
```

这说明当前内环本质上是：

- 比例项
- 积分项
- 简单微分差分项

也可以理解为比较轻量的离散 `PID`/`PI-D` 形式。

### 12.4 积分限幅

不同模式下，积分限幅绑到各自的最大 duty：

- Buck：`buck_max_duty_tick`
- Boost/Mix：`boost_max_duty_tick`

例如：

```c
if (s_POWER_currentIntegral > (int32_t)s_POWER_controlValue.buck_max_duty_tick)
{
    s_POWER_currentIntegral = (int32_t)s_POWER_controlValue.buck_max_duty_tick;
}
```

作用：

- 防止积分无限增长
- 防止软启动期间积分项把占空比直接顶满
- 减少模式切换后的积分冲击

### 12.5 模式对应的 duty 输出

#### Buck

```c
s_POWER_controlValue.buck_duty_tick = s_POWER_getAppClampDuty(s_POWER_i0,
                                                              BSP_POWER_BUCK_DUTY_MIN_TICK,
                                                              (uint32_t)s_POWER_controlValue.buck_max_duty_tick);
```

同时 Boost 侧保持：

- 轻载时最小导通
- 正常时同步最小值

```c
s_POWER_controlValue.boost_duty_tick = (s_POWER_buckLightLoad != 0U)
                                           ? BSP_POWER_BOOST_DUTY_MIN_TICK
                                           : BSP_POWER_BOOST_DUTY_SYNC_MIN_TICK;
```

#### Boost

Buck 侧直接拉到最大：

```c
s_POWER_controlValue.buck_duty_tick = BSP_POWER_BUCK_DUTY_MAX_TICK;
```

Boost 侧由内环输出调节：

```c
s_POWER_controlValue.boost_duty_tick = s_POWER_getAppClampDuty(s_POWER_i0,
                                                               BSP_POWER_BOOST_DUTY_MIN_TICK,
                                                               (uint32_t)s_POWER_controlValue.boost_max_duty_tick);
```

#### Mix

Buck 侧保持同步最大：

```c
s_POWER_controlValue.buck_duty_tick = BSP_POWER_BUCK_DUTY_SYNC_MAX_TICK;
```

Boost 侧继续调制。

可以理解为：

- `MIX` 更像一个过渡带
- 当前实现的主调制自由度仍集中在 Boost 侧

## 13. Buck 轻载处理

当前代码专门有 Buck 轻载逻辑：

```c
#define POWER_CTRL_BUCK_LIGHT_LOAD_ENTER_RAW    70
#define POWER_CTRL_BUCK_LIGHT_LOAD_EXIT_RAW     175
```

逻辑：

- 电流低于 `70 raw`，进入轻载
- 电流高于 `175 raw`，退出轻载

进入轻载后：

```c
s_POWER_controlValue.boost_duty_tick = BSP_POWER_BOOST_DUTY_MIN_TICK;
```

否则：

```c
s_POWER_controlValue.boost_duty_tick = BSP_POWER_BOOST_DUTY_SYNC_MIN_TICK;
```

这个机制的目的，是减轻轻载下同步整流过强带来的反向抽能、啸叫和大纹波问题。

## 14. PWM 输出方式

代码最后通过 HRTIM 寄存器写入比较值：

```c
__HAL_HRTIM_SETCOMPARE(&hhrtim1,
                       HRTIM_TIMERINDEX_TIMER_A,
                       HRTIM_COMPAREUNIT_1,
                       BSP_POWER_HRTIM_PERIOD_TICK - (uint32_t)s_POWER_controlValue.buck_duty_tick);
```

说明：

- Buck 侧 A 通道使用的是“周期减去 duty”的写法
- 这通常意味着硬件配置里占空比极性或比较方向与直觉相反

同时：

```c
__HAL_HRTIM_SETCOMPARE(&hhrtim1,
                       HRTIM_TIMERINDEX_TIMER_D,
                       HRTIM_COMPAREUNIT_1,
                       (uint32_t)s_POWER_controlValue.boost_duty_tick);
```

Boost 侧 D 通道则直接写 duty。

这也是为什么调试时最好同时看：

- `buck_duty_tick`
- `boost_duty_tick`
- `pwm_a_compare`
- `pwm_d_compare`

因为“控制器内部 duty”和“定时器最终比较值”不是完全同一个量。

## 15. 状态机详解

状态机：

```c
typedef enum
{
    POWER_STATE_INIT = 0U,
    POWER_STATE_WAIT,
    POWER_STATE_RISE,
    POWER_STATE_RUN,
    POWER_STATE_ERR,
} POWER_state_t;
```

### 15.1 `INIT`

调用 `s_POWER_initAppValues()` 初始化运行数据，然后转到 `WAIT`。

### 15.2 `WAIT`

主要逻辑：

- 停止 PWM
- 等待使能
- 等待没有故障
- 等待输入电压通过 UVLO
- 等待一段时间后进入 `RISE`

这里的等待计数：

```c
#define POWER_CTRL_WAIT_TICK_COUNT 200U
```

由于 `WAIT` 在慢速 `200Hz` 节拍里推进，所以大约是 `1s` 左右的等待。

### 15.3 `RISE`

这是软启动阶段，由子状态机控制：

```c
POWER_SOFTSTART_INIT
POWER_SOFTSTART_WAIT
POWER_SOFTSTART_RUN
```

#### `SOFTSTART_INIT`

- 停 PWM
- 把 Buck / Boost 最大占空比都压到最小
- 清 PID
- 更新参考值
- 把软启动电压参考设成目标值的一半

#### `SOFTSTART_WAIT`

短暂等待，给硬件稳定时间。

#### `SOFTSTART_RUN`

- 若 PWM 还没开，则启动 PWM
- 每次慢速节拍逐步增加：
  - `buck_max_duty_tick`
  - `boost_max_duty_tick`

也就是说：

- 软启动并不是直接爬升 duty 输出
- 而是逐渐放开允许的最大 duty
- 同时电压外环还会受到 `vout_softstart_ref_raw` 的限制

这是“双重限幅”的软启动思路，比较稳。

### 15.4 `RUN`

正常运行状态。

若失能，则回到 `WAIT`。

### 15.5 `ERR`

错误状态会：

- 停止 PWM
- 模式置 `NA`
- 如果故障恢复清零，再回到 `WAIT`

## 16. 保护逻辑详解

保护逻辑在 `s_POWER_checkAppProtection()` 中完成。

### 16.1 VIN 欠压锁定

阈值：

```c
#define POWER_CTRL_VIN_UVLO_START_MV 5500U
#define POWER_CTRL_VIN_UVLO_STOP_MV  5200U
```

这是带迟滞的 UVLO。

### 16.2 VIN 过压

```c
#define POWER_CTRL_VIN_OVP_MV 50000U
```

超过立即进故障。

### 16.3 短路保护

判据：

```c
if ((iout_ma > POWER_CTRL_SHORT_CURRENT_MA) && (vout_mv < POWER_CTRL_SHORT_VOLTAGE_MV))
```

也就是：

- 电流很大
- 输出电压很低

才认为是短路。

### 16.4 OTP

看的是板温：

```c
if (board_temp_mc >= s_POWER_ctrlSettings.otp_set_mc)
```

### 16.5 VOUT OVP

连续保持若干次慢节拍才进入故障：

```c
#define POWER_CTRL_OVP_HOLD_TICK_COUNT 2U
```

### 16.6 OCP

同样只在 `RUN` 态生效，并需要持续一段时间：

```c
#define POWER_CTRL_OCP_HOLD_TICK_COUNT 10U
```

这样可以减少启动或扰动时的误触发。

## 17. 故障恢复机制

在 `s_POWER_updateAppFaultRecovery()` 中：

- `VIN_UVP`：输入恢复后自动清
- `SHORT`：按计数器定时重试
- `IOUT_OCP`：按计数器定时重试

相关参数：

```c
#define POWER_CTRL_FAULT_RETRY_TICK_COUNT 400U
#define POWER_CTRL_FAULT_RETRY_LIMIT      10U
```

因为恢复逻辑在 `200Hz` 慢节拍执行，所以 `400` 次约等于 `2s`。

也就是说：

- 故障后不会立刻频繁重启
- 会隔一段时间再试一次

## 18. 风扇与指示灯

### 18.1 风扇

风扇有两种模式：

- 手动固定档位：`fan_set_permille != 0`
- 自动温控：按板温分段

自动分段大致是：

- `<35C`：停转
- `40C` 左右：中低速
- `65C+`：全速

### 18.2 指示灯

状态很简单：

- 故障：红灯
- 正常运行：绿灯
- 上电等待/软启动/UVLO：蓝灯
- 其余：全灭

## 19. 快照生成逻辑

`POWER_getAppSnapshot()` 是调试和协议观察的重要函数。

关键设计点：

1. 如果平均值已经初始化，优先返回滤波后的量
2. 如果还没初始化，则直接用实时量换算
3. `loop_current_feedback_ma` 根据当前模式动态选择 `IIN/IOUT`
4. `loop_current_reference_ma` 返回外环当前真实输出值
5. `voltage_loop_reference_mv` 返回当前电压参考值，不一定等于用户设置值

这意味着你能通过快照直接区分：

- 用户设置值
- 当前外环参考值
- 当前内环参考值
- 当前反馈值
- 当前硬件比较值

这对调试非常有帮助。

## 21. 当前实现里的注意点

虽然结构已经比之前更合理，但当前实现还有几个值得特别注意的点。

### 21.1 电压环输出到电流参考的缩放是工程参数

```c
#define POWER_CTRL_VOLTAGE_LOOP_TO_CURRENT_SHIFT 9
```

这个右移 9 位是为了把电压环输出压到合适量级，不是严格从物理模型推出来的。

后续如果你觉得：

- 外环太软
- 外环太猛
- 一进入 CC 就很突兀

这里是一个重点调整点。

### 21.2 内环系数目前还是经验量

```c
#define POWER_CTRL_CURRENT_LOOP_KP 6
#define POWER_CTRL_CURRENT_LOOP_KI 3
#define POWER_CTRL_CURRENT_LOOP_KD 1
```

当前内环不是按完整小信号模型推出来的，而是工程化实现。

### 21.3 `MIX` 模式更偏向 Boost 逻辑

当前 `MIX` 下：

- 电流采样选 `IIN`
- Boost 侧调制
- Buck 侧基本固定在同步区间

这意味着 `MIX` 并不是完全独立的一套控制器，而更像 Boost 的过渡带。

### 21.4 模式判定使用 `vout_ref_raw`

模式切换依据当前参考而不是当前实测电压，这有利于稳定，但在某些极端扰动下也可能导致：

- 系统尚未真正进入目标工作区
- 模式却已提前切换

是否要改，取决于你后续上板观察结果。
